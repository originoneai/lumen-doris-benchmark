# 评测协议

## 发布角色

- 环境管理员将指定的一个 Doris 基准库接入 Lumen。每个库有独立的来源标识和业务日历。按候选包提供材料，允许参测系统合理检查列与少量样本。
- 参测者只用实际客户端提交 `candidate/tasks.jsonl` 中当前轮的自然问题，同时按 `roles.json` 就对应用户实际授权。每个任务从独立会话开始，跟进轮共享该次会话。保存回答、工具或查询回执、所用材料、错误与返工。安全任务以对应角色的读写和可见范围为判定依据。
- 评分者持有独立的 `evaluator/`，从实际结果抽取数值、结构化模型和决策。同一数值分别从原始业务流水和 Doris SQL 交叉验证。语义解释、报告、拒绝理由和业务后续由独立复核者检查证据并签收。

评测日期为 2026 年 3 月 1 日。角色和当前自然问题是参测上下文。任务 ID、内部答案、判分标签、标准关系和参考 SQL 是评测侧材料。

## 观察文件

评估端按 `case`、`turn` 和 `check` 关联。标量可用十进制字符串，分组结果由 `key` 和 `value` 组成。排名检查保留次序，其余分组按键比对。金额和比例以任务约定单位计算，保留两位。语义字段和安全决策进行精确匹配。报告和解释使用参测者、独立复核者及可定位的产物证据。

```jsonl
{"case":"retail/SING-01","turn":1,"check":"total_yuan","value":"1234.56"}
{"case":"retail/RPT-01","turn":3,"check":"final_report","performer":"agent-run-A","reviewer":"reviewer-B","outcome":"pass","evidence":"artifacts/quarterly-review.md#final"}
```

上例中的值用于说明格式。标准答案以生成的评估包为准。

## 多轮和报告工作流

每个长任务有独立业务请求、任务空间和产物路径。用首轮启动分析，并按顺序提交至少两次有实质内容的追问。留存报告初稿、用户要求的修改、工具及结果引用、独立复核、最终文档和交付回执。保留故障或失败材料。缺少必要阶段时，把该长任务记为待复核或未完成。发布包通过检查是基准可用性的证据，正式客户端验收由实际会话和归档材料证明。

## 口径

- 建模任务考查主键、粒度、关联和多对一方向。本体任务考查指标口径、日期归属和下游去重。
- 单轮任务考查数值及业务口径。多轮任务考查时间、条件与上轮信息是否正确继承。探索任务查验基线、拆解与解释边界。
- 报告保留来源和可复查明细。反例要求明确识别错误前提、证据不足或需要澄清。安全任务检查授权范围、数据最小化和只读边界。
- 汇总分子保留每个结果的状态和分母，同一数仓的分组结果、定量校验、人工判断和实际安全配置可分别核对。
